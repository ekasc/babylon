## Snapcompact: Babylon-native context-archive projection

A non-destructive context archive for long Babylon sessions. When Pi compacts, snapcompact renders the outgoing conversation into a small set of PNG frames plus an exact-token dictionary, stores the archive in Babylon-owned state (never in the project), and injects it back as a **transient projection** before every LLM call. The canonical Pi session is never mutated.

## How it works

```
Pi session_before_compact ──► buildArchive() ──► ArchiveStore (immutable generations)
        │                                                   │
        ▼                                                   ▼
  CompactionEntry with marker            Pi context event (before every LLM call)
  (details.snapcompactGeneration)        ──► header text + PNG frames as ImageContent
```

- **Trigger**: Pi's real `session_before_compact` extension hook — the same boundary as textual compaction. No second context estimator, no prompt-time decoration.
- **Injection**: Pi's `context` event rebuilds the message list before each LLM call; the extension appends the archive header (raw text) and frames (real `ImageContent`: base64 PNG, `image/png`). Transient only — the canonical session stays untouched.
- **Fallback**: model without vision, archive unavailable/mismatched, budget errors, or store I/O errors → Pi's normal textual compaction, unchanged.
- **Ownership**: `pickStrategy` is the only decision owner (settings mode + model caps + archive availability). Default mode is `summary` — zero snapcompact work unless opted in.

## Pipeline

| Stage | Module | Notes |
|---|---|---|
| Serialize | `serializer.ts` | Role-tagged blocks (¶user/¶assistant/¶thinking/¶tool/¶result), tool/result pairing, image stripping, truthful coverage (`firstKeptEntryId`/`lastKeptEntryId`/`keptCount`/`omittedTrailing`) |
| Symbols | `symbol-dictionary.ts` | High-value token extraction; capped (`maxSymbolCount`, `maxDictChars`) |
| Frame plan | `frame-plan.ts` | Non-overlapping line ranges; overflow recorded via an omission-marker frame — no silent holes |
| Render | `renderer.ts` + `png-encoder.ts` + `font.ts` | Pure-JS PNG (color type 0, bit depth 1), 5×7 font, deterministic; dictionary substitution with `[E001]` anchors ≥12 chars, first occurrence verbatim |
| Persist | `archive-store.ts` | `<stateDir>/snapcompact/<key>/generations/<genId>/` immutable frames + atomic manifest swap; staging dir + `rename(2)`; 0o600/0o700; integrity validation |
| Profiles | `model-profiles.ts` | Per-model frame dims, `maxFrames`, image-token estimates, archive byte caps |
| Strategy | `strategy.ts` | Single decision owner |
| Extension | `extension.ts` | `session_before_compact` + `context` handlers |
| Eval | `eval.ts` + scripts | Offline coverage + live retrieval scaffold (see below) |

## Crash safety

Archive writes are immutable generations: frames are staged in a temp directory, validated (count + non-empty), then atomically renamed into `generations/<genId>/`; the manifest is written via temp-file + `rename(2)`. A crash mid-write leaves the previous generation intact. Corrupt/missing frames raise `ArchiveIntegrityError` and the extension falls back to textual compaction.

## Budgets

`maxSourceChars`, `maxSymbolCount`, `maxDictChars`, `maxFrames`, `maxArchiveBytes` enforced in `build.ts` (`ArchiveBudgetError` → fallback). The serializer drops whole trailing messages (recorded in `omittedTrailing`) rather than truncating mid-line.

## Evaluation — two separate outputs, honestly labeled

1. **Offline coverage** (`pnpm eval:snapcompact`, no LLM): what the archive *contains* — truthful serializer coverage fields, frame-plan hole check, dictionary anchor check, request byte/token estimates, build time. Compares raw / prefix-control (deterministic 1500-char prefix, **not** Pi's LLM summary) / snapcompact / snapcompact-dict. Report persisted to `docs/perf/snapcompact-coverage.txt`.
2. **Live retrieval scaffold**: `emitLiveRequest()` emits the exact vision-model request (header text + base64 frames + dictionary + questions) to `docs/perf/snapcompact-live-request.json`. With `BABYLON_LIVE_MODEL_URL`/`BABYLON_LIVE_MODEL_KEY`/`BABYLON_LIVE_MODEL` set, the harness POSTs an OpenAI-compatible request and grades exact-match answers. **The offline harness does not claim to measure vision-model retrieval** — bitmap OCR/retrieval accuracy requires the live run with real creds.

Build performance (`pnpm bench:snapcompact`, median of 2): end-to-end <60ms at every scale (10k→1M source chars capped by `maxFrames: 8` + 60KB transcript budget).

## Not changed

- Pi session files, Pi's own compaction path (untouched when mode = `summary`)
- No Oh My Pi dependency, no Rust/Bun, no native deps (renderer is pure JS)
- No LLM call during archive generation (deterministic)
